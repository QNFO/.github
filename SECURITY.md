# Security policy

QNFO is maintained by one person, Rowan Brad Quni-Gudzinas. This policy applies to every repository in the [QNFO organisation](https://github.com/QNFO) that does not carry its own `SECURITY.md`.

## Reporting a vulnerability

Report privately. Please do not open a public issue or pull request that describes the problem.

1. Use the **Report a vulnerability** button on the Security tab of the affected repository (GitHub private vulnerability reporting), where the button is shown, or
2. email [rowan.quni@qnfo.org](mailto:rowan.quni@qnfo.org) with the repository or URL in the subject line.

## What to include

- The repository and file, or the URL and endpoint, that is affected.
- The version, branch or commit you looked at.
- Steps to reproduce, and what you expected to happen instead.
- The impact as you understand it, and a suggested fix if you have one.
- For an exposed credential, token or key: where it is, not the value. Do not copy it into the report and do not use it.

## Scope

- Every repository in the QNFO organisation.
- The qnfo.org websites, including papers.qnfo.org.
- Credentials or personal data exposed anywhere in the above, including in git history.

## What to expect

Reports are handled by a single maintainer on a best-effort basis. There is no bounty and no promised response time.
